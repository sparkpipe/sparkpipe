# Laguna multidev lane (TP8xPP2, spark0..sparkf)

`tools/laguna_multidev_run_family.sh` prepares one rank's private runtime
root and execs `sparkpipe_model_residentd` attached to a running weightd.
`tools/laguna_multidev_lane.py` generates the deployment and the per-rank
adapter configuration. Neither starts a weightd.

## Topology

Rank r runs on `spark{hex(r)}`, pipeline stage r//8, TP rank r%8. The
deployment keeps `rank_index == stage_index == r`; the adapter derives the
TP rank and pipeline stage from it. Each rank attaches the operator-placed
pack `/home/{host}/sparkdata/laguna-s-2.1.bf16.tp8pp2/packs/laguna_stage.tp8.pp2.stage{r//8}.rank{r}.lgsp`
(the file name carries the global rank). `SPARK_TP_MESH_RANKS` is the
stage's eight global ranks.

## Required inputs

Nothing that selects the lane, the weightd, the root or the KV size has a
default. The wrapper refuses to start without:

| Variable | Meaning |
|---|---|
| `LAGUNA_LANE` | weightd mesh lane and port lane, 0..15 |
| `LAGUNA_MODE` | `queue` (inside a spark_queue job) or `direct` (dev run) |
| `LAGUNA_WEIGHTD_SOCKET` | absolute path of the running weightd socket; `SPARK_WEIGHTD_SOCKET` from the environment is not used |
| `LAGUNA_KV_BACKING_BYTES` | KV backing cap in bytes |
| `LAGUNA_KV_PAGE_CAPACITY` | logical and physical KV page capacity |

Queue mode reads `SPARK_QUEUE_ATTEMPT`, `SPARK_QUEUE_RUNTIME_ROOT`
(`/tmp/sparkqueue-<attempt>`), `SPARK_QUEUE_RANK`, `SPARK_QUEUE_SIZE` (16)
and `SPARK_QUEUE_PORTS`, checks that every listener of the lane is inside a
reserved range, and derives the collective identifier from the attempt id.

Direct mode reads `LAGUNA_RANK`, `LAGUNA_COLLECTIVE_ID` (the same positive
decimal on every rank) and `LAGUNA_RUNTIME_ROOT`, which must be
`/tmp/sp-laguna-lane<L>` so every node's deployment names the same root.
There is no port reservation in direct mode: record the run in
`NODE_BUDGET.md` and check the lane's ports are free first.

Optional: `LAGUNA_PREBUILT_DIR` (install built artifacts instead of
building), `LAGUNA_EXPERT_POOL_BYTES` and `LAGUNA_SPINE_BUDGET_BYTES`
(override the budgets derived from the pack's `.experts` sidecar),
`LAGUNA_WORKING_SET` (warm the smoke-expert `.wset` before launch) and
`LAGUNA_GDB` (run the resident under batch gdb).

## Port ledger for lane L

| Block | Range | Use |
|---|---|---|
| control | 23000+16L .. +15 | residentd control listener, one per rank |
| collective | 53000+16L .. +7 | host TCP collective, group-local: both stages reuse the eight numbers on disjoint hosts |
| transport | 64000+16L | transport control base (topology only for host-rdma) |
| session | 23168+64L .. +55 | 8x8 session matrix and its hc mirror, topology only under the weightd mesh |

Lane 11: control 23176-23191, collective 53176-53183, transport 64176,
session 23872-23927. `tests/test_laguna_multidev_lane.py` checks lane 8
against the laguna entry of `tools/devcycle/lane_assignments.json` and that
lane 11's blocks do not overlap any other registry lane. The session blocks
of lanes 0 and 1 (23168-23295) overlap the control blocks of lanes 10-15;
lane 0's session block is topology only today, but check the ports before a
direct run.

## Budgets

`--budgets PACK` prints the weightd expert-pool bytes (the whole pack in
2 MiB chunks, which is what the daemon charges on acquire) and the spine
bytes (the complement of the expert spans plus 256 for the aligned spine
allocation), both from the `.experts` sidecar. A missing or stale sidecar is
regenerated by `tools/laguna_multidev_experts_manifest.sh`.

## Pack digest

`packs/pack.sha256` is the first 64 characters of the deployed `.sha256`
when it is well formed. Otherwise the wrapper hashes the pack and, when a
`.receipt.json` is present, refuses a digest that disagrees with it. The
wrapper no longer writes a digest cache into the shared sparkdata tree.

## Example: direct run on lane 11

On node r (checkout in `~/sp-laguna/src`, artifacts in `~/build-laguna/prebuilt`):

```sh
systemd-run --user --unit=sp-laguna-rd -p MemoryMax=24G \
  --setenv=LAGUNA_LANE=11 --setenv=LAGUNA_MODE=direct --setenv=LAGUNA_RANK=$r \
  --setenv=LAGUNA_COLLECTIVE_ID=1100001 --setenv=LAGUNA_RUNTIME_ROOT=/tmp/sp-laguna-lane11 \
  --setenv=LAGUNA_WEIGHTD_SOCKET=/tmp/spark_weightd.sock \
  --setenv=LAGUNA_KV_BACKING_BYTES=8589934592 --setenv=LAGUNA_KV_PAGE_CAPACITY=2048 \
  --setenv=LAGUNA_PREBUILT_DIR=$HOME/build-laguna/prebuilt \
  --setenv=SPARK_TP_WAIT_MODE=hardware --setenv=CUDA_ENABLE_COREDUMP_ON_EXCEPTION=0 \
  bash $HOME/sp-laguna/src/tools/laguna_multidev_run_family.sh
```

systemd-run does not pass the calling shell's environment, so every input
goes through `--setenv`.

## Warm receipt

`tools/devcycle/laguna_warm_receipt.sh` times weightd warms of the node's own
pack against a running weightd. It needs `LAGUNA_WEIGHTD_SOCKET` (absolute
path of a live socket; there is no default and `SPARK_WEIGHTD_SOCKET` is not
read). `build/weightd_warm` takes no lane, so the receipt takes none. Optional: `LAGUNA_WARM_RUNS` (default 5) and
`LAGUNA_EXPERT_POOL_BYTES` (default: the whole-pack 2 MiB chunk basis from
`--budgets`, which is what the daemon charges on acquire).

It generates the `.experts` sidecar when missing, emits the rank's smoke
working set, splits it into 512-pair chunks (the lease group limit) and
warms them in sequence. Run 1 is the daemon-cold warm of the pack, run 2 the
warm-daemon preload, later runs the steady state. `RUN-WALL` is the whole
invocation; the per-chunk `WSET-WARM elapsed_ms` is the acquire and release.
Both working-set bases (raw and 2 MiB chunked) are printed.
