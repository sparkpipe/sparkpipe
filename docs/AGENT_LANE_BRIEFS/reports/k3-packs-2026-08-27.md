## P4 — rank-0 smoke: BLOCKED by K3 module bugs (evidence below; coordinator owns fixes)

The packs are proven down to the C loader: SparkK3PackOpen PASS and 22/23
layers bind PASS on the deployed rank-0 pack (probe:
tests/test_k3_bind_layers.c, this branch). The daemon ready line could not
be reached; each blocker, with the exact evidence:

1. Adapter .so is not dlopen-able: `undefined symbol: cuTensorMapEncodeTiled`
   — the Makefile's K3_SERVING_ADAPTER rule links -lcudart but not -lcuda
   (the runner uses the driver API for TMA). Worked around in-lane by
   relinking with -lcuda; INTEGRATION REQUEST A.
2. Adapter .so does not export the generic interface symbol: residentd
   dlsym's `SparkModelServingAdapterGetInterface`
   (SPARK_MODEL_SERVING_ADAPTER_INTERFACE_SYMBOL); the K3 adapter exports
   only `SparkK3ServingAdapterGetInterface` (every other family exports the
   generic name). `error: symbol lookup error: undefined symbol:
   SparkModelServingAdapterGetInterface (fatal)`. Worked around in-lane via
   tools/k3_serving_adapter_export_shim.c; INTEGRATION REQUEST B.
3. Descriptor inconsistency: stage_layer_counts = {24,23,23,23} repeated 4x
   (sums 372) while stage_count=16 and layer_count=93 — the loader's
   descriptor validation rejects the adapter
   (`initialize=invalid_argument status=1 phase=adapter_load`).
   INTEGRATION REQUEST C.
4. THE HARD BLOCKER — module bind drift on layer 92. SparkK3BindLayer
   classifies layers by `(layer_index % 4u) != 3u` and misses the trailing
   global layer 92 (one-indexed 93), which the checkpoint, the contract
   (hybrid_attention.final_layer_is_global) and the module's own
   SparkK3LayerIsMla (spark_k3_pool_sizing.h) all treat as MLA. The pack is
   correct; the binder misclassifies, so SparkK3ModuleInitialize fails with
   VALIDATION_FAILED (9) on any stage-3 pack:

```
$ k3_single_step k3.stage3.rank00.pack --pp1      (slice derived from manifest)
INIT FAIL 9                                       (SPARK_STATUS_VALIDATION_FAILED)

$ /tmp/k3_bind_layers k3.stage3.rank00.pack       (per-layer probe)
pack first=70 layers=23 total=93
layer 70 bind PASS (binder kind: KDA)
...
layer 91 bind PASS (binder kind: MLA)
layer 92 bind FAIL (binder kind: KDA)             <- the drift
```

   The runner-step gate's default mode also reports INIT FAIL 9 because it
   hardcodes stage_index=0 (stage tables demand layers 0-23); that part is
   test-usage, not a bug — the --pp1 mode is the correct invocation for a
   non-zero stage pack and it still fails at layer 92's bind.
5. Adapter destroy corrupts the heap when called after a FAILED runner
   init, masking the real status: `double free or corruption (top)` in
   SparkK3StageRunnerDestroy <- K3ServingInitialize (gdb bt captured).
   INTEGRATION REQUEST E.
