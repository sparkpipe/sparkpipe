## Shard design (block-correct)
GGML `ne[0]` is the fastest/input axis and quant blocks pack along it.
- `split1` (safe at any granularity): token_embd/output (vocab 7552/rank),
  attn_q_b/kv_b/attn_gate, indexer q_b (head axis on dim 1).
- `split0` (block-aligned 1024): attn_output (o_proj, head input axis).
- `split2` (slab): fused routed experts `[in, ff, 256]` → 16 experts/rank;
  decomposed attn_k_b/attn_v_b heads.
- `replicate`: q_a (2048 lora-out can't divide at 256-block granularity),
  shexp + dense FFN, router, norms, hc params, indexer smalls — 4.28 GB/rank.
- Per rank: 18.72 GB, 2134 tensors. **No MTP tensors in the GGUF** (blocks
  0–77 only); the MTP layer exists only in the FP8 safetensors reference.

## Incidents + lessons (read before reusing any of this)
1. **Cache-resident sha256 proves nothing.** The first download "verified"
   by reading straight out of page cache; cold reads then hung. Every
   verification of a just-written big file must run after
   `sync; echo 3 > /proc/sys/vm/drop_caches`.
2. The hang itself was a **transient ceph client wedge** (Ds folio_wait),
   not corruption: after drop_caches the file scanned clean end-to-end at
   3.5 GB/s and cold-sha'd bit-perfect. Name quarantines until proven.
3. **GB10 multi-stream small-write pathology**: 16 interleaved ~1 MB writers
   jam page writeback to ~9 MB/s (even local NVMe); large per-rank sequential
   writes sustain 1.1 GB/s. Buffer per file, flush big. (Watchdog +
   vm.dirty_bytes tuning kept as belt-and-suspenders.)
4. Two writer bugs caught by gates before placement: slice length used the
   full-tensor size; slice offsets mixed data-section-relative with absolute.
   The manifest-vs-file-size cross-check is what exposed them — keep it.
5. `pkill -f` self-match killed my own ssh twice. Bracket-trick always.
