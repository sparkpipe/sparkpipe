## The decode-frame hunt (the hard part)

With the daemon up, the batch's prefill leg produced a real token
(`token_id 198`) but the decode submission was refused
`invalid_argument` inside the module's `ValidateFrame` — a SILENT check.
Three instrumented probe cycles (adapter-side, host .so only — no GPU):

1. probe 1 (`792d08d`): the daemon's decode submission is PROVABLY
   coherent — prefill `(lane0=0 slot0=0 seqid=1 pos0=0 rows=7)` then
   decode `(lane0=0 slot0=0 seqid=1 pos0=7 reqgen=1)`: same resident slot,
   next-position 7 matches the module's committed continuity. The TP4
   adapter contract test is green, so it is the module/frame seam.
2. probe 2 (`442c182`): the full frame context is well-formed
   (`ctx_flags=0x3` = KV_BLOCK_TABLE|DECODE_BATCH_VIEW, block table
   abi=1 bytes=56 blk_tok=64 lane_count=64 lane_cap=64 stride=128, all
   pointers non-null, buffers READ/4/WRITE/4 slot 1).
3. fix attempt `8f16efd`: BuildFrame left `decode_batch`/`prefill_view`
   uninitialized (only `context` was zeroed) and the module's view
   validators check `reserved0` EXACTLY — stack garbage is a
   nondeterministic refusal (prefill got lucky zeros, decode did not).
   Fixed on the lane; kept as a real correctness fix regardless.
4. probe 3 (`754e409`): the module itself now carries line-numbered
   `VF_CHECK_FAIL id=N line=L` prints on EVERY ValidateFrame refusal
   site; the module was re-published through GPU revalidation, so the
   refusal names itself.

## Traps hit tonight (all real, all now documented)

1. **Old tree is a different program.** The coordinator's own
   `qwen27b-inference-smoke4` re-proved it live at 20:0x:
   `model_residentd deployment=io_error` from the Aug-19
   `~/sparkdata/qwen38.fp8.tp1/bin`. Do not patch it; fresh main only.
2. **stage_pack_path must be relative** to runtime_root on current main
   (commit `6d4ffe6`).
3. **Driver link needs explicit cudart/stdc++** via `--cc-arg` (runbook
   invocation).
4. **Module publish cannot skip the GPU validator** — the module library
   resolution refuses records whose `validation_state != "passed"`.
5. **GB10 page cache**: 78-81 GB buff/cache before drop; `sudo -n sh -c
   'sync; echo 3 > /proc/sys/vm/drop_caches'` freed it to 2 GB. Dropped
   before the validator leg and again before daemon start.
6. **Queue zombie reaping**: a task whose bash dies without writing the
   node-side exit file stays `running` and holds its node until TTL
   (build-1: "pid gone without exit file" after 6 s; build-2 held spark5
   ~40 min after its log was complete). I cancelled my own zombie
   (`spark_queue.py cancel --id q27b-build-2`); dispatcher owners may want
   to look at the exit-file path.
