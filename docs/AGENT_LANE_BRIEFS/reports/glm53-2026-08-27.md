## Findings that change the plan (all shape-evidenced)

1. **No fused KDA projection exists in the checkpoint.** The
   `modules_to_not_convert` list contains `qkv_proj` and
   `fused_qkvbfg_a_proj` module names, but the safetensors index has
   NEITHER. KDA layers store separate `q_proj/k_proj/v_proj` [8192,4096]
   BF16 + depthwise `q/k/v_conv1d` [8192,1,4]. M2's name mapping maps from
   these separate tensors (good news: closer to K3's `kda_qkv_beta` split
   layout than the fused name suggested).
2. **`b_proj` [64, 4096] is a per-head scalar beta** (one row per head),
   not a [8192,4096] projection. `dt_bias` [8192] is per-head-per-channel.
   K3's packed KDA layout must be checked against both shapes in M2.
3. **Rope-0 MLA confirmed at the tensor level**: `q_b_proj` [16384,1536]
   = 64 heads x 256 nope ONLY; `kv_a_proj_with_mqa` [512,4096] = pure
   lora latent (glm52: [576,4096] with rope segment). Rope exists only in
   the indexer (`wq_b`/`wk`, 128-dim, interleaved).
4. **The indexer has NO wq_a** — `wq_b` [4096,1536] consumes the MLA
   `q_a_layernorm` output directly: the MLA q_a path IS the indexer q_a.
   One packer consequence: indexer and MLA share the 1536 lora; the pack
   cannot treat them as independent components.
5. **k_norm has a bias** ([128] weight + [128] bias). Donor check needed:
   does dsv4-0731's k_norm carry a bias? (M2 mapping item.)
6. **MTP layer 45 has NO hyper-connections** (45 HC layers = 0..44 only),
   but IS a full DSA layer (MLA + indexer + MoE 288+1) + eh_proj
   [4096,8192]/enorm/hnorm/shared_head.norm. HC bring-up must special-case
   layer 45.
7. **`index_share_for_mtp_iteration: true`** and indexer_tensors are
   present on layer 45 too (12 indexer layers = 11 DSA + MTP).
8. FP8 set is exactly: experts + shared experts + dense mlp (layers 0-2) +
   MLA q_a/q_b/kv_a/o_proj on DSA layers. ALL KDA tensors, ALL indexer
   tensors, hc_*, router, A_log/dt_bias (F32) are BF16/F32. Full list in
   contract `precision.fp8_quantized_patterns`.
9. `use_full_rank_gate` absent from config (K3 sets true) — recorded in
   the contract as an open item; must be resolved from kernel semantics
   (or HF reference source) before wiring `kda_gate` in M3.

## Findings this milestone

1. **The reference semantics are now pinned from source.** transformers
   main `models/glm5_next/modeling_glm5_next.py` (2385 lines, fetched to
   .lane_cache) confirms:
   - Text stack is **NoPE end to end** — no rotary anywhere (only the
     vision tower has rotary_pos_emb). The indexer never rotates;
     `indexer_rope_interleave` is vestigial. (Coordinator recorded this in
     the assessment as commit 30e87ec; my header carries the porting note.)
   - Forget gate = `-5.0 * sigmoid(exp(A_log_h) * (f_b(f_a(x)) + dt_bias))`
     per head per channel; beta = `sigmoid(b_proj(x))` per head; core is
     kimi delta attention with in-kernel qk L2-norm — the K3 kernel chain.
   - Indexer scores 4-token POOLS: pool key = softmax over pool positions
     of `(gate_j + ape_j)` weighted sum of keys; per-head relu scores at
     128^-0.5; head aggregation weights_proj(x) * 32^-0.5; select 512
     pools -> 2048 tokens + tail(3), output width 2051, invalid = -1.
   - mHC: streams init to the embedding expanded x4; pre=sigmoid+eps,
     post=2*sigmoid, comb=softmax+eps then 20-iteration sinkhorn; final
     head is an UNWEIGHTED MEAN of streams then RMSNorm (dsv4 uses a
     weighted hc_head — simpler here).
   - MoE: fp32 router, sigmoid + noaux_tc (n_group=1), norm top-k,
     scale 2.5, swiglu with limit-10 clamps — the glm52 router config
     verbatim at 288 experts.
2. **KDA gate question RESOLVED (coordinator note 2).** The K3 module's
   `kda_gate_weight` is full-rank [96*128, 7168] consumed by ONE GEMM +
   `LmOutputGateKernel` (sigmoid). glm53 has no full-rank g_proj: the gate
   is low-rank g_a[128,4096]+g_b[8192,128]. `LmBoundedDecay`
   (inference/kernels/linear_attn.cuh) is EXACTLY glm53's forget gate
   (verified line-by-line: `exp(lb*sigmoid(exp(A_log)*(logit+bias)))`).
   So: use_full_rank_gate is a FIELD-GEOMETRY difference, not just a flag
   — the port packs `kda_decay_gate_down_weight` (fused f_a|g_a rows,
   k3's own pack-V2 vocabulary) + `kda_gate_up_weight` and chains two
   GEMMs exactly like the existing decay path. NO new kernels.
3. **The indexer donor is glm52, not dsv4.** glm52's stagepack already
   reads the byte-identical tensor names (`indexer.wq_b/wk/weights_proj/
   k_norm.weight+k_norm.bias`), 32 heads x 128, topk 2048 — glm53's
   indexer IS glm52's indexer plus the kpool compressor. The dsv4-0731
   indexer compressor (ape[4,256]+wkv+wgate+norm at 256ch, ratio-4 layers
   only) does NOT map 1:1 to glm53's compressor (ape[4,128]+gate[128,
   hidden], every DSA layer, no wkv/norm): mechanism donor, not rename.
4. Round-trip closes: all 414 census patterns resolve to pack fields
   except exactly the 347 vision patterns (out of scope).
