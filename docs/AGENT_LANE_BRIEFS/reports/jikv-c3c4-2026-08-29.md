## C3 — MEASURED tier bandwidth in admission

The pager now owns the one number C3 says is worth measuring: an EMA
(alpha = 1/2) over OBSERVED page-in and page-out throughput — payload
bytes over elapsed microseconds — in
`SparkKvPagerStatistics.measured_bytes_per_second` (with
`measured_bandwidth_samples`). The pager has no time source of its own:
the clock is INJECTED (`SparkKvPagerClockFunction` +
`clock_context` in the configuration), so a host test advances a fake
clock per poll and the measurement is deterministic; NULL keeps the EMA
at 0 and the admission arithmetic falls back to the tier's NOMINAL
configured bandwidth. Samples fold from three places: the inline
page-out leg (clock-bracketed `backing_write` in
`SparkKvPagerEvictWriteback`), the async page-out leg (the worker
brackets its write; the elapsed sample rides the completion record and
folds on the owning thread — the EMA stays single-writer), and the
page-in leg (the restore demand loop ticks the clock per poll, from
read-issue to landing). Degenerate samples (no clock, no bytes, no
elapsed — a demand hit with no transfer behind it) fold nothing.

The admission arithmetic consumes it: `SparkKvPagerAdmission` ABI 1->2 —
the former `reserved0` slot is now `restore_slack_microseconds` (the
struct keeps its size; the ABI bump makes the reinterpretation loud; a
legacy abi answers INVALID_ARGUMENT). With slack > 0 the decision adds a
bandwidth bound to the capacity bounds: the pager's AGGREGATE restore
debt (every allocated non-resident block still holding its backing —
committed and in-flight parks alike — counted in the same single scan
that yields C1's parkable pool) plus this admission's own park-outs must
cross the caller's slack at the MEASURED rate
(`admission_queued_bandwidth` when it cannot). With nothing measured yet
the tier's nominal figure stands in; with no number at all the capacity
checks alone decide — never queue on ignorance. With slack 0 the answer
is byte-for-byte the pre-C3 capacity-only decision, which is why every
existing pager scenario runs unmodified.

Proof (tests/test_jit_kv_c3c4.c, scenario 1 + fences): two identical
fixtures, identical history (two parks, one committed lane B, one
rewind), only the fake drive's speed differs (4 polls/read vs 1) and the
same fake-clock step: the slow fixture's EMA lands strictly below the
fast one's; the test derives each fixture's prediction from the debt the
pager itself counts and picks a slack strictly between them — the SAME
admission then QUEUES on the slow fixture and ADMITS on the fast one,
touching nothing when it queues; without a slack the same admission is
the pre-C3 ADMITTED answer; a no-clock fixture with a slow NOMINAL
figure queues too (fallback active, `measured_bytes_per_second` still
0).

## C4 — ASYNC PARK WORKER

The park write-out leaves the arena's clock. The eviction path
(`SparkKvPagerEvictWriteback`) stages the block payload into the park
entry's OWN plane (per-entry staging in the configuration's
`park_staging` — the arena can reuse the evicted device slot before the
write lands), reserves the tier record INLINE (so `slots_in_use` — the
number admission's park-headroom check reads — is exact at enqueue
time), enqueues, and returns OK. A worker thread (config
`park_queue_blocks` > 0; 0 keeps the pre-C4 inline behavior) runs ONLY
the backing-write leg, and the OWNING thread publishes completions:
`SparkKvPagerPollParkCompletions` (called at the top of Admit and
Restore, available standalone) applies each completion record — OK:
`CommitWrite` (the readable-index insert) + BACKING_VALID + the
page-out receipt; IO-class failure: `AbortWrite` (the tier slot
returns) + the B1 degrade (BACKING_VALID/DIRTY cleared,
`write_back_degraded_block_count` incremented) — exactly the transition
the inline write-back's failure path applies, applied at publish time,
never a wedge, never a resident-trusted byte.

Synchronization is SPSC rings, no mutex: the park ring (owning thread
produces, worker consumes) and the completion ring (reverse), cursor
ordering via acquire/release, capacity-bounded so slot reuse trails its
consumer by a whole ring. A park between enqueue and publish is visible
in BOTH of its windows to `SparkKvPagerParkIsInFlight` (the queued ring
AND the published mid-write slot, set before the pop and cleared after
the completion push), matched by block AND exact payload digest — so a
restore offer on a mid-write park answers BUSY (C2 translates: QUEUED)
instead of falling through to the tier and recomputing bytes the pager
is about to publish. Degenerate answer at worst once more (a completion
pushed but not yet drained answers BUSY, then the next offer drains and
proceeds). Queue full or dedup (already_present) → the write completes
inline on the arena's clock — slower, never dropped, never wedged.

TERM safety follows the W2a weightd discipline: an atomic stop flag the
owning thread stores (`SparkKvPagerShutdown`), a 200us poll quantum
(`SPARK_KV_PAGER_PARK_POLL_QUANTUM_MICROSECONDS`) bounding how late the
flag is seen — the true bound on a park is one backing write, never a
wake-up promise. Shutdown joins, then completes every staged park the
worker left INLINE on the owning thread (same write leg, same
publication) and drains: every reservation resolves commit-or-abort,
every staged payload is accounted. Idempotent; parks requested after
shutdown complete inline (worker off).

Proofs (scenarios 2-5): a park stuck mid-write does not block an
admission that fits — lane C even PARKS THROUGH the stuck write
(admitted, exact tier-slot accounting); the mid-write park dispatches
QUEUED with zero page-ins and zero recomputes, then the same offer
completes bit-exact; an IO-class write degrades at publish (abort +
drop + recompute, slot returned, dispatch answers RECOMPUTE) beside a
healthy park dispatching READY bit-exact; TERM mid-park (one write
done, one STUCK mid-write, one queued) resolves all three committed
with no tier leaks and the mid-TERM bytes restore bit-exact; shutdown
is idempotent; a park AFTER shutdown completes inline on the arena's
clock. Configuration fences: queue depth above the ring refused, async
without staging (or undersized staging) refused, inline needs nothing,
worker start failure unwinds the evict binding loudly.
