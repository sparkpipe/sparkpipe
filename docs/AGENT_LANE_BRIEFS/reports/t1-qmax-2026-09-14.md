## Root cause of the final blocker (exact numbers from the placed bytes)

The placed W1 entry (layer 0, every layer identical): rows=65536,
cols=8192, weight_format=4 (SPARK_STAGEPACK_FORMAT_WEIGHT_FP8_E4M3_F32B128),
payload_bytes=268435456 = rows*cols/2, scale_bytes=33554432 = rows*cols/16.

Codec-6 (NVFP4) sizing: U8-packed payload (2 values/byte) + one e4m3
scale byte per 16 values — exactly what tools/qwen38_stagepack.py writes
under EXPERT_CODEC=nvfp4 ("codec-6 sizing" in its own comment) while
STAMPING weight_format=4. The module loader computes code 4 as real fp8:
payload rows*cols = 512 MiB (2x too big) and scale
(rows/128)*(cols/128)*4 = 128 KiB (256x too small) -> ValidateEntry
rejects the entry, fail-closed, before any expert byte is mapped.

The shared contract already has the right code:
SPARK_STAGEPACK_FORMAT_WEIGHT_NVFP4_PACKED = 8, and the shared kernel
suite fully implements SPARK_LM_WEIGHT_FORMAT_NVFP4_E2M1 = 8 (batched
linear + grouped expert nvfp4_plane paths). The qwen38max module maps
neither: no NVFP4 case in PayloadBytes/ScaleBytes, no format-8 mapping
in FillLinearView, and the grouped-expert W2 launch hardcodes
SPARK_LM_WEIGHT_FORMAT_MXFP4_E2M1.
