# qwen38max TP16 enablement — 2026-08-30

Operator: "let's do TP16 first" — single pipeline stage, all 16 nodes
tensor-parallel, ahead of the TP4xPP4 plan.

## Design

TP16 on this geometry (512 experts, GDN 16/128 key/value heads, 64
query / 4 KV heads × 256, hidden 8192, moe_int 2048) cuts everything
cleanly except attention KV (4 heads vs 16 ranks). Fix: **kv-head
replication** — K/V projections and the KV cache shard by
`min(degree, kv_heads)` whole heads; the rank's slice sits at
`floor(rank · kv_heads / degree)`, so ranks 0–3 share kv head 0, 4–7
head 1, 8–11 head 2, 12–15 head 3. Each rank's 4 query heads fall
inside one GQA group (group 16, query block 4), so the shared head
serves the whole group and the attention output all-reduce still sums
exactly once per query head. Per-rank KV cache at TP16 is 1 head — a
quarter of the TP4 per-rank cache. For degrees dividing kv_heads the
new arithmetic is byte-identical to the old `rank × local` form.

Changes: model-header macros (SHARD_COUNT/LOCAL_KV_HEAD_COUNT/
RANK_KV_HEAD_BASE/LOCAL_KV_DIMENSION), format-v2 SHARD_KV_HEAD_ROWS
axis + feasibility, module KV sizing, cuda prepare/decode kernels +
launcher guards, packer/verifier kv-axis divisor + rank slice.

## CPU proofs (spark0, real AMD checkpoint)

- 1-layer packs at tp16 ranks 0/1/3/5/15: **20/20 byte-traced samples
  verified each** (quark-mxfp4 source).
- Replication semantics cross-checked directly on attention-layer
  (layer 3) packs: K/V slices identical across ranks 0/1/3 (shared
  head 0), distinct at rank 5 (head 1) and 15 (head 3); query slices
  all-distinct.
- Full 92-layer rank pack dry-run: **96.22 GiB** — under the 110GiB
  law but tight once runtime + KV cache land (≈10G headroom; the
  replicated embedding+lm_head alone is ~8G/rank — a future
  column-shard of lm_head is the obvious relief valve).
- Module + kernels compile clean on sm_121a (spark7), archive builds.
