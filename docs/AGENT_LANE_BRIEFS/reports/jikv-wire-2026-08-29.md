## Unit 1 — the frame ops (the module seam, family form)

`modules/dsv4_resident_decode_stage/source/spark_dsv4_jit_kv.c/.h` — the
two function pointers the pager's `SparkKvPagerBlockView` contract calls,
implemented with the design's frame-context op codes:

- `SparkDsv4KvFramesSave` (KV_BLOCKS_SAVE_OUT 0x00001000u): device planes
  -> pager staging, key plane then value plane (the pager's staging
  contract).
- `SparkDsv4KvFramesRestore` (KV_BLOCKS_RESTORE_IN 0x00002000u): staged
  bytes -> device planes.

EVERY op is STAGED first — a `SparkDsv4KvFrameOp` descriptor (op code,
plane addresses, byte counts, staging pointer) recorded in the context;
that descriptor is exactly what the frame context executes on a spark.
Two backends:

- TERM (host): the device planes are host mappings; the built-in
  `SparkDsv4KvFramesSubmitHostCopy` runs the byte movement.
- SPARK_FRAME_OPS: the frame-context submission installed at the
  spark-side module open (`SparkDsv4KvFramesAcceptSparkReceipt` is the
  receipt gate — a host build never holds one). WITHOUT the receipt the
  op is staged, counted, and REFUSED UNSUPPORTED: loud, nothing runs, the
  pager staging is untouched, nothing is degraded (UNSUPPORTED is not an
  IO-class status, so the arena's B1 degrade does not swallow it). The
  proof drives this end to end: the refused admission fails loud with
  zero page-outs and an all-zero staging buffer; accepting the receipt,
  the SAME admission parks four blocks through the frame-submit seam.

The seam validates the pager's view (abi/descriptor, block_count 1, plane
byte counts == the arena strides, non-null addresses) — a broken view is
refused before anything is staged.

## Unit 2 — parkability is ONE predicate

`SparkKvCacheArenaBlockIsParkable` (cache/kv_cache.c + decl in
spark_kv_cache.h): the resident-eviction selector's STRUCTURAL exclusions
(ALLOCATED + RESIDENT, no RESIDENCY_RESERVED, no residency references) as
a single answer, placed in the arena so it cannot drift from the selector
it mirrors. The pager's admission pool count now CALLS it instead of
restating the flag test inline (kv_pager.c Admit scan, net -6 lines), so
admission, the selector, and any adapter's decision count the same thing.

`SparkDsv4JitKvDecideParkability` (module side) is the serving-adapter
condition for a deployment: it counts parkable / pinned / non-resident
blocks over the arena THROUGH the shared predicate and enforces the
active-set rule — a block listed active that the predicate calls parkable
fails the condition (BUSY with `unprotected_active_count` named): pin the
active set or shrink the dispatch window before offering work. The proof
shows the full agreement loop: pinned actives -> pager admission QUEUES
on the same zero pool; one unpin -> the condition counts exactly one
parkable, per-block predicate names it, admission parks exactly that
block (page-out history newest entry), pinned neighbors survive
bit-exact; once parked, the still-listed block leaves the park
condition's jurisdiction (non_resident count) and becomes the C2 gate's.

## Unit 3 — C2: dispatch gates on restore complete

`SparkKvPagerDispatchBlock` (spark_kv_pager.h + kv_pager.c) — the gate is
the restore, not a hint:

- ONE restore path feeds it (`SparkKvPagerRestoreBlock`, the same
  digest-verified page-in every rewind takes; no parallel fast lane).
- READY is answered only AFTER the RESIDENT flag is re-read and verified
  — never on trust; an OK-without-residency would be INTERNAL_ERROR.
- BUSY (tier saturated, make-room write-back in flight) answers QUEUED:
  the dispatch waits, the repeated offer IS the queue — nothing wedged,
  nothing dropped, no half-restored residency behind the answer
  (statistics: dispatch_queued).
- NOT_FOUND answers RECOMPUTE — a block with no backing bytes (a B1-
  degraded block) is never dispatched on partial state
  (dispatch_recompute).
- Hard failures stay loud (a scenario bug during development surfaced the
  restore's honest CAPACITY_EXCEEDED when a lane's reservation was left
  uncommitted — exactly the loud behavior the contract wants).
- Statistics: dispatch_requests / dispatch_ready / dispatch_queued /
  dispatch_recompute appended to `SparkKvPagerStatistics`.

Proofs: parked-block dispatch QUEUES while both tier records are pinned
(11 repeated offers healthy, zero page-ins, block stays parked); the same
offer completes once the tier yields, bit-exact; a resident block
re-gates READY with no second restore; the degraded block answers
RECOMPUTE while its healthy neighbor restores bit-exact. The positive
paths re-offer through transient QUEUED (bounded, every non-READY answer
asserted QUEUED) — the queue-not-wedge discipline carried to dispatch.
