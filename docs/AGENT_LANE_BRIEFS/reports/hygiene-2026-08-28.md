## H3 — test_model_pipeline_client FLAKE

Reproduced: 3/25 and 2/10 runs abort at
`TestModelPipelineStopResidents` (test_model_pipeline_client.c:426).
Instrumented teardown captured the race precisely:

    test_model_pipeline_client rank=0 expected_exit=1 ... exited=1 exit=0

Root cause: the post-failure teardown pinned exit status 1 for every
rank. `SparkModelPipelineClientDestroy` closes the client sockets; a
residentd that processes the EOF first fails its run loop (io_error,
exit 1), while a SIGTERM that lands first stops the loop cleanly
(exit 0). Rank 0 (TCP entry, TERMed first, immediately after Destroy)
loses that race intermittently. Both exits are correct residentd
behavior — the assertion over-specified an uncontrollable ordering.

Fix (tests/, mine): the failure teardown accepts exactly {0,1} per rank
and requires at least one rank to have observed the failure (a silently
clean fleet still fails); the clean teardown keeps exit==0; mismatch
diagnostics print rank/status detail. Verified 30/30 green (was ~12%
red). Commit `10fc5ba` (pushed).
