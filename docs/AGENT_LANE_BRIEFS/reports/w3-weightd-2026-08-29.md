# W3 weightd lane: the POSIX-fd export + consumer import/map tier (2026-08-29)

Lane: `lane/w3-weightd` (worktree /tmp/lane-w3weightd, pushed — never merged by
me; integration requested below).
Brief: docs/WEIGHTD_DESIGN.md + the W2b report's "Next experiment" item 1
(docs/AGENT_LANE_BRIEFS/reports/w2b-weightd-2026-08-29.md) — the tier that
report named as gating the real-GPU dsv4 attached-binding receipt. Three
units, in order: (1) the daemon exports an attached arena's physical chunks
as POSIX shareable fds; (2) the consumer imports and maps them at its own
VA (the `device_handle` pid-local stopgap replaced); (3) the staged GPU
receipt extends to the import legs.
Commit: on `lane/w3-weightd` (base ce04d4d → origin/main 90baf2e, W2b merged).

## What landed (1 commit)

1. `runtime/spark_weightd.c` (+361) — the daemon's export half:
   - ADDITIVE wire kinds `EXPORT=9` / `EXPORT_RESULT=10` with
     `SPARK_WEIGHTD_IPC_ABI_VERSION` UNCHANGED (1): an old daemon closes a
     connection that sends EXPORT, which the consumer reads as its usual
     fallback signal — never as wrong bytes. All five W2a contract tests and
     both W2b suites pass UNMODIFIED.
   - The fd payload rides the SCM_RIGHTS ancillary of the reply frame, never
     the body. The kernel caps one message's fd payload (SCM_MAX_FD 253) and
     a 100 GiB arena is ~51k 2 MiB chunks, so the chunk set is delivered in
     position-addressed batches of at most
     `SPARK_WEIGHTD_EXPORT_BATCH_MAX` (64) — the reply names the arena's
     whole geometry (`chunk_bytes`, `chunk_count`) plus this batch's offset
     and count.
   - ACCESS SCOPING (the OS-level discipline): the socket is 0600 (the KV
     backing's owner-only file law carried to the socket), and the EXPORT
     request's arena generation must be one THE CONNECTION holds an attach
     reference for — the attach ref IS the export capability; a second
     connection (or a post-detach connection) gets NOT_FOUND. Exported fds
     get FD_CLOEXEC in the daemon (chunk fds never survive an exec).
   - Exact-once fd delivery: the fds stage on the connection until the first
     COMPLETED sendmsg (the kernel takes its own references at send time),
     then the daemon's copies close; EAGAIN/EINTR retry the same fds on the
     next Step; every error/close path drains staged fds. The flush keeps
     the W2b PENDING/retry contract.
2. `runtime/spark_weightd_attach.c` (+283) + both weightd headers (+117) —
   the consumer's import/map: `SparkWeightdAttachImportMap(outcome,
   expected_arena_bytes, timeout, reason)`:
   - Receives the batches (`SparkWeightdClientExportBatch`, a new client
     call in spark_weightd.c: recvmsg with MSG_CMSG_CLOEXEC where available,
     belt-and-braces fcntl elsewhere; validates frame shape, request id,
     batch offset echo, and fd count == batch_count — any mismatch closes
     every fd already received and fails closed).
   - THE IDENTITY CHECK before anything maps: the chunk set must COVER the
     CALLER's expected byte range (`chunk_bytes * chunk_count >=
     expected_arena_bytes`, overflow-safe; the caller passes its own pack
     claim, not the daemon's echo), the geometry must be multipliable and
     inside `SPARK_WEIGHTD_MAP_CHUNK_COUNT_MAX` (65536 — the 110 GiB law at
     2 MiB chunks tops out well under it, so a larger claim is a lying
     frame, never an arena), and the batches must tile [0, chunk_count)
     exactly. Failure = "import_short"/"import_shape", attach released,
     nothing mapped.
   - Then per fd: `cuMemImportFromShareableHandle` (fd closed immediately
     after — the import holds the driver's own reference), the consumer's
     OWN `cuMemAddressReserve` span, per-chunk `cuMemMap` at the pack
     offset, and `cuMemSetAccess` RW over the whole span. On success
     `outcome->device_handle == outcome->map_base` is valid for the process
     lifetime — borrowed-slice binding needs no further change.
   - TEARDOWN: `SparkWeightdAttachRelease` first unmaps every mapped chunk
     (exact pairs), releases every imported handle, frees the reservation
     and the handle array — then closes the client WITHOUT detaching: the
     daemon reaps the socket, drops the reference, and the arena stays
     warm. The W2b close-only contract is preserved; the map teardown rides
     in front of it.
   - Every "not mapped" outcome returns OK with a reason and the attach
     released ("import_exchange", "import_shape", "import_short",
     "import_handle", "import_map", "import_access", or the daemon
     refusal's status name) — the unconditional-fallback contract extends
     untouched. A lazy-context bootstrap (cudaFree(0)) precedes the driver
     calls so a fresh consumer process can import immediately.

## Design notes / honest limits (for the reviewer)

- RW, not read-only: the design doc's marketplace scribble protection says
  consumer maps read-only; this lane maps the consumer span RW with
  cuMemSetAccess per the lane brief (matching the daemon's own RW mapping).
  The consumer never writes the arena in any in-repo path, but the
  enforcement flip (CU_MEM_ACCESS_FLAGS_PROT_READ on the consumer leg) is a
  one-constant change once a consumer-side read-only receipt exists — left
  deliberately visible, not forgotten.
- Batch-count bound: one EXPORT exchange per 64 chunks (~800 exchanges for
  a 51k-chunk 100 GiB arena) — microseconds each, but the GPU receipt's
  timings will say whether a larger SCM_RIGHTS batch (up to 253) is worth
  it; the constant is one line.
- The stub's export copies bytes at export time (heap pages cannot alias
  across an fd); the real driver aliases. Sound for every lifecycle proof
  because arena bytes are frozen at cold load, and it is exactly what the
  spark-gated receipt re-proves aliased on hardware.
- The wire stayed ABI 1: additive kinds only. A pre-W3 daemon closes an
  EXPORT connection (kind unknown) and the helper falls back with
  "import_exchange" — graceful both directions.
- SCM_RIGHTS fd-exactness under partial socket writes is handled by
  staging-until-first-completed-send; the receiving side additionally
  cross-checks fd count == batch_count, so a torn or lying transfer can
  only fail closed.
- The daemon still counts CLAIMED arena bytes against the 110 GiB law (the
  W2b note about granularity slack stands; W3 adds no device memory — the
  consumer map aliases the daemon's chunks).
