## How this serves the scoreboard

Every serving rank re-reads and re-uploads its whole pack at every process
start — the cold-start line item on all 16 nodes and every family — and
every code redeploy pays it again. W1 landed the fast cold-path primitives
(pipelined load, 8x identical-digest SHA-256). W2a lands the thing that
makes both count once per node instead of once per process: one
family-neutral daemon per node that owns the weight arenas keyed by content
identity (model, revision, topology, pack SHA-256, geometry fingerprint, ABI
version). Two attaches of one identity share ONE arena; a code-only redeploy
re-attaches warm in milliseconds; and the operator's NO-2x budget is
enforced by the daemon, not by operator discipline: updates go
stop-attach-start and the resident peak is provably one arena.

## What landed (1 commit)

1. `include/sparkpipe/spark_weightd.h` (326 lines) — the surface:
   - `SparkWeightdIdentity` = (model[64], revision[128], topology u32,
     pack_sha256 hex[65], geometry_fingerprint u64, arena_bytes u64, ABI
     u32) + `Prepare` (canonicalizes padding/terminators/digest shape) +
     `Equal` (plain memcmp over the canonical form — content addressing
     cannot depend on the sender's zero hygiene).
   - Fixed-frame wire protocol (magic `WDIS`, ABI 1):
     HELLO/HELLO_ACK/ATTACH/ATTACH_RESULT/DETACH/DETACH_RESULT/RECLAIM/
     RECLAIM_RESULT; every exchange opens with HELLO, every response echoes
     the request id, every frame is validated against its exact size.
   - Server API (Create/Step/Run/Destroy + introspection) and client API
     (Connect/Attach/Detach/Reclaim/Close) with hard deadlines.
2. `runtime/spark_weightd.c` (1515 lines) — the core:
   - Poll-driven, NO worker threads: one non-blocking `Step` (accept, drain,
     answer); `Run` = Step loop with a 20 ms quantum and an ATOMIC stop-flag
     load — the TERM path cannot be starved by a peer (the no-TERM-immunity
     rule, by construction).
   - Arena map: up to 16 arenas; hits bump a CONNECTION-scoped refcount
     (one attach per identity per connection — a second claim is
     DUPLICATE); consumer death (EOF/POLLHUP) drops every ref that
     connection held. Detached arenas stay resident COLD — the warm-redeploy
     win — reclaimed only by budget pressure (oldest-first, attach refs
     follow the swap-delete) or an explicit RECLAIM.
   - Cold path verifies BEFORE allocating, through ONE open handle:
     size claim vs fstat, streamed digest (the W1 fast `SparkSha256Update`
     bulk path), load, then a size+mtime re-check closing the in-flight
     rewrite window; any mismatch = HASH_MISMATCH/IO_ERROR with nothing
     resident. Wrong-size claims are INVALID_ARGUMENT before any allocation.
   - THE NO-2x GATE: an attach that cannot fit under the ceiling after
     reclaiming every cold arena fails CAPACITY_EXCEEDED and allocates
     NOTHING — a live arena is never evicted. Updates therefore go
     stop-attach-start (the design's operator constraint) and the resident
     peak over an update is exactly one arena.
   - Memory-space discipline: arenas are device-private cudaMalloc — the
     named W2b stand-in for cuMemCreate + CU_MEM_HANDLE_TYPE_POSIX_FD
     export (2 MiB pages, read-only consumer maps); staging is host
     anonymous memory; the staging→arena copy is named cross-space.
   - Client: blocking-with-deadline exchange; a dead daemon (EOF
     mid-exchange, refused connect) fails the call closed — never a handle
     it cannot vouch for.
3. `node/weightd.c` (157 lines) — the daemon process, placement per the
   design (per-node, sibling of `sparkpipe_model_residentd`):
   `spark_weightd --socket <path> [--device-bytes-max <bytes>]` (env
   SPARK_WEIGHTD_SOCKET / SPARK_WEIGHTD_DEVICE_BYTES_MAX; flag beats env,
   env beats default). The DEFAULT ceiling is the operator 110 GiB device
   law; deployments on shared nodes LOWER it — nothing in the daemon can
   raise it. Ready line on stdout is the launch gate; TERM prints
   `spark_weightd stopped arenas=N bytes=N` and exits 0.
4. `tests/test_weightd.c` (785 lines, cuda-stub only) + Makefile
   registration (links like model_residentd: real cudart where CUDA_HOME
   exists, the host stub where it does not; the test is stub-pinned like
   test_stage_module_common).

- SHARED REFCOUNT: client A attaches identity I (1 MiB deterministic pack,
  digest from the W1 `SparkSha256File`) → cold load, refcount 1, arena_count
  1. Client B attaches the same identity → loaded_from_pack=0 (warm),
  refcount 2, arena_count STILL 1, same arena_generation, same device
  handle. Same-connection re-attach → DUPLICATE (one map per process).
  B dies WITHOUT detaching → server reaps the EOF → fresh client C attaches
  warm: refcount back to 2, arena_count 1, no reload (consumer-death path +
  cold retention in one observation).
- NO-2x: ceiling 1.5 arenas. Attach identity J while I serves →
  CAPACITY_EXCEEDED, arena_count still 1, resident still 1 MiB (nothing
  allocated; a second connection still gets I warm at refcount 2 — the
  refusal harmed nothing). STOP (both holders detach → refcount 0, I stays
  cold-resident), START (attach J) → the daemon reclaims cold I, loads J:
  arena_count 1, resident 1 MiB. PEAK OVER THE WHOLE UPDATE: ONE ARENA.
  Then I cannot come back while J serves (CAPACITY_EXCEEDED the other way).
- TERM: the real `build/sparkpipe_weightd` binary, spawned by the test, its
  pid captured at fork: serving a real cross-process attach (refcount 1,
  loaded 1), then SIGTERM → waitpid: `WIFEXITED && WEXITSTATUS == 0`,
  socket path unlinked (stat fails), stderr contains

  next attach FAILS CLOSED against the dead daemon.

## Design notes / honest limits (for the W2b lane and the reviewer)

- W2a loads synchronously inside `Step` (the NO-2x budget rules out
  background loads): a cold load briefly delays other clients' attaches.
  Fine for the skeleton; W2b should keep the synchronous contract but may
  pipeline the read+copy inside the load with the W1 pipeline (the daemon's
  cold path inherits it, per the design).
- `device_handle` in ATTACH_RESULT is the pid-local stand-in for the
  exported shareable handle; it means NOTHING across processes until W2b
  lands cuMemCreate + POSIX-fd export + consumer cuMemMap read-only +
  2 MiB pages. The client API shape is already the import surface.
- The post-load size+mtime re-check closes the in-flight rewrite window at
  mtime granularity (ns on the fleet's fs); the residual adversarial
  same-instant in-place rewrite is caught downstream by the determinism
  receipts, not here. Digest-before-allocate remains the primary gate.
- Budgets/bounds (16 arenas, 16 connections, 8 attaches/connection) are
  per-daemon HOST memory; the sixteen-topology operational win fits. The
  device ceiling is separate and is the 110 GiB law by default.
- RECLAIM is exposed as an explicit client call (maintenance handle) in
  addition to the automatic cold-reclaim-under-pressure.
