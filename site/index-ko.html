01 왜

토큰이 아니라 시간

토큰 단위 API는 같은 코드베이스에 몇 번이고 요금을 매깁니다.

API 캐시는 짧은 세션을 위해 만들어졌습니다. Claude에서는 기본 5분 유지되며, 1시간 캐시는 쓰는 데 입력 가격의 2배, 5분 캐시는 1.25배가 듭니다. Kimi의 기본값도 5분입니다. 그래서 휴식, 회의, 브랜치 전환, 서브에이전트마다 전체 컨텍스트의 비용을 다시 내고, 프리필되는 동안 기다립니다. 에이전트 작업에서 $20–50 충전이 금방 바닥나고, 구독 한도가 점심 전에 차는 이유입니다.

하루의 순간토큰 단위 API내 플릿

고객에게는 청구서가 더 작은 비용입니다. 1분 넘게 기다리면 다른 창으로 넘어가게 되고, 문제로 다시 돌아오는 데는 기다린 시간보다 더 많은 시간이 듭니다. 나만의 플릿에서는 컨텍스트를 한 번 계산하고, 그다음 턴은 모두 직전 턴이 멈춘 곳에서 시작합니다.

02 내 플릿

남는 것

고객만을 위해 일하고 고객의 코드를 기억하는 플릿.

고객에게 고정

플릿 전체가 고객의 요청만 처리합니다. 공유 대기열도, 공유 캐시도 없고, 플릿 자체의 속도 외에는 속도 제한도 없습니다. 다음 주를 계속 예약하는 동안 다른 누구도 그 시간을 예약할 수 없습니다. 일이 많으면 플릿을 더 보유하세요. 낮용, 밤용, 병렬 리뷰용으로.

남는 작업 상태

플릿에 8 TB의 캐시, 노드당 1 TB를 짝 노드에 미러링합니다. 요청은 가장 긴 캐시된 프리픽스를 자동으로 재사용하므로 슬롯을 관리할 필요가 없습니다. 다른 고객의 그 플릿 예약이 시작되거나 고객의 마지막 시간 후 24시간이 지나면 삭제됩니다. 플릿 밖 사본도, 백업도 없습니다. 보관소가 아니라 작업 공간으로 다루세요. 장애로 두 사본이 모두 사라지면, 캐시를 다시 구축하는 동안 플릿 24시간분을 적립해 드립니다.

고객 저장공간

모든 플릿에 저장소, 데이터셋, 어댑터와 모델을 위한 4 TB, 노드당 500 GB를 캐시처럼 미러링합니다. 보유한 어느 플릿으로든 내보내고 복원할 수 있으며, 보존하려는 것은 매일 백업하세요.

고객의 도구

Claude Code, Codex, Cursor 또는 OpenAI 호환 도구에 엔드포인트와 키를 넣고, 계정에서 하는 모든 일은 sparkpipe CLI로 할 수 있습니다.

오픈 모델 18종

Kimi K3, GLM 5.3, DeepSeek V4.1 Flash와 국산 K-EXAONE 2.0, A.X K2, Solar Open 2 등을 각 게시자의 라이선스에 따라 제공합니다. 모델 전환은 20~80초입니다. 플릿 목록에 모든 모델의 실측 속도가 있습니다.

한국에서만

요청과 데이터는 저희가 한국에서 운영하는 장비에서만 처리되며, 다른 AI 서비스로 보내지 않습니다. 한국은 EU 적정성 결정과 영국의 적정성 결정을 받았으므로, 유럽의 개인정보는 별도의 이전 계약 없이 고객의 플릿으로 올 수 있습니다. 계약 상대방은 한국법을 따르는 한국 회사입니다.

03 기능

코드에 대한 작업

지시하면 플릿이 고객의 코드를 다룹니다.

기능은 저희가 만들어 고객이 보유한 플릿에서 실행하는 소프트웨어입니다. 계정, API 또는 CLI에서 시작하거나 예약하세요. 설정은 기능이 스스로 합니다. 처음 실행하는 기능이 저장소를 가져옵니다. 결과는 고객 저장공간과 아침 보고서에 남고, 기능이 만든 것은 고객의 것입니다. 기능은 계속 늘어납니다.

고객의 상태

저장소 가져오기
저장소를 복제하거나 동기화하고, 푸시를 따라가며, 파일, 심볼, 이력을 지도로 만듭니다.
캐시 구축과 갱신
가장 적게 바뀌는 부분부터 프리필하고, 푸시마다 바뀐 부분만 다시 계산합니다.
미리 프리필
지정한 브랜치와 모듈을 웜 상태로 두고, 턴 사이에 다음에 쓸 만한 것을 프리필합니다.
세션 이어가기
어제의 에이전트 세션을 웜 상태로 두어, 멈춘 곳에서 이어갑니다.
내보내기와 복원
저장공간, 캐시 스냅숏, 드래프트 모델과 어댑터를 보유한 어느 플릿으로든 옮깁니다.
매일 백업
지정한 저장공간 경로를 고객의 버킷이나 서버로 매일, 바뀐 부분만 복사합니다.

문제 찾기

그날의 변경 리뷰
변경마다 diff만이 아니라 코드베이스 전체에 비추어 리뷰하고, 발견마다 테스트로 확인합니다.
다른 모델의 의견
같은 리뷰를 다른 모델로 실행하고 의견이 일치하는 곳을 표시합니다.
보안 감사
메모리 안전성, 동시성, 인젝션, 비밀정보, 의존성을 재현 방법과 함께 순위별로 보고합니다.
테스트와 퍼징
바뀐 코드의 단위 테스트와 퍼저를 작성해 실행하고, 크래시를 보고합니다.

작업 처리

야간 에이전트
작업 목록을 처리하고, 작업마다 테스트 결과와 함께 브랜치를 남깁니다.
코드베이스 전체 변경
이름 변경, API 마이그레이션, 포팅을 파일 단위로, 빌드와 테스트를 마친 브랜치 하나로 만듭니다.
코드베이스 전체에 묻기
질문이나 지시 하나를 모든 파일이나 모듈에 실행하고 답을 모읍니다.
문서 최신 유지
아키텍처 노트, API 문서, 코드 지도를 푸시마다 갱신합니다.
아침 보고서
밤사이 만든 모든 것을 한 페이지에, API 호출 한 번으로.

모델

드래프트 모델 학습
저장소와 세션으로 학습시켜, 고객의 새 코드에서 추측 디코딩이 모델의 토큰을 매주 더 많이 받아들이게 합니다.
고객의 코드로 모델 평가
고객의 테스트나 평가 세트를 모든 제공 모델과 고객 모델에 실행해, 작업마다 가장 좋은 모델을 고릅니다.
고객 모델 검증
고객의 모델과 드라이버를 고객의 참조 출력과 대조합니다.
어댑터 학습
제공 모델이나 고객 모델의 어댑터를 고객의 데이터로 학습시킵니다.
학습 데이터 생성
원본 모델의 라이선스가 허용하는 경우, 고객 모델을 위한 학습 데이터를 생성합니다.

코드를 빌드하거나 실행하는 기능은 고객의 플릿 안 샌드박스에서, 고객이 허용하지 않는 한 네트워크 없이 실행됩니다. 플릿의 보유자가 바뀌면 저희 이미지로 복원하므로, 한 고객이 실행한 것이 다음 고객에게 닿지 않습니다.

04 고객의 모델

비공개 모델 목록

자체 모델을 학습시켰나요? 나만의 플릿에서 서비스하세요.

  1. 업로드

    CLI나 API로 가중치를 고객 저장공간에 올립니다. 플릿의 메모리에 들어가는 모델이면 됩니다. Kimi K3의 1.56 TB도 들어갑니다.

  2. 드라이버 추가

    모델 계열 인터페이스와 코딩 에이전트용 안내서를 공개하므로, 고객의 에이전트가 드라이버를 작성할 수 있습니다. 대부분의 새 모델은 이미 있는 계열 스케줄을 재사용합니다.

  3. 검증

    기능이 고객의 플릿에서 모델을 고객의 참조 출력과 대조해 일치 여부를 보고합니다. 저희 모델이 통과하는 것과 같은 검증입니다.

  4. 사용

    고객의 모델 목록에만, 제공 모델 옆에, 같은 엔드포인트 뒤에 나타나며 모든 기능과 함께 쓸 수 있습니다.

05 이용 방법

네 단계

데모 시간, 그다음 나만의 플릿.

  1. 계정 열기

    회사의 법인명 또는 본인 이름, 6자리 코드로 확인한 업무용 이메일, 고객 계약 동의. 비밀번호는 없습니다. 그다음 HC를 원하는 만큼 삽니다.

  2. 데모 시간 예약

    데모 플릿 전체를 시간 단위로, 최대 7일 앞까지, 시간당 1 HC. 고객의 도구를 연결해 코드베이스로 시험해 보세요.

  3. 플릿 고정

    이용 가능한 플릿의 첫 주를 다음 월요일부터 예약합니다. 모든 플릿이 보유되어 있으면 최소 144 HC를 잠가 대기 명단에 들어갑니다.

  4. 유지

    마지막으로 예약한 주의 일요일 00:00 전에 다음 주를 예약하면 플릿은 계속 고객의 것입니다. 더 많은 주를 미리 보유할수록 예약하는 모든 주의 할인이 커지며, 최대 20%입니다.

대기 명단은 가장 큰 잠금이 먼저, 같으면 먼저 들어온 순서입니다. 플릿은 매주 일요일 00:00(KST)에 배정되며, 잠금 전체로 지불할 수 있는 만큼의 주가 예약됩니다. 고객은 자신의 순위와 대기 중인 잠금 수만 볼 수 있습니다. 예약을 멈추면 그 일요일에 플릿은 대기 명단으로 넘어가고, 다음 고객이 시작할 때 캐시와 저장공간이 삭제됩니다.

주는 월요일 00:00부터 일요일 24:00(KST)까지이며, 일요일이 무료입니다. 출시 시 플릿 8개.

장애15분 넘게 장애가 있었던 예약 시간은 저희 기록에 따라 자동으로 HC로 돌려드립니다. 점검은 플릿당 주 최대 3시간이며 같은 방식으로 적립됩니다
결제토스페이먼츠를 통한 원화 결제(국내·해외 카드, 계좌이체, 가상계좌, 간편결제), CoinPayments를 통한 USDC 또는 USDT, 또는 대한민국 밖의 고객 명의 계좌에서 보내는 미국 달러 계좌이체(SWIFT). 한국 사업자는 카드 매출전표나 전자세금계산서를 받습니다
부가가치세10%가 더해집니다. 대한민국에 사업장이 없는 고객의 미국 달러 계좌이체(SWIFT)는 0%입니다
환불저희가 HC 서비스 제공을 중단하거나 고객의 귀책 없이 계정을 닫는 경우를 제외하고 없습니다. 대기 명단에 잠긴 HC가 기다리는 동안 소멸하게 되면 환불합니다

가격은 이 웹사이트에서 정하며 바뀔 수 있습니다. 이미 산 HC와 예약한 주는 그 가격을 유지합니다. SparkPipe 고객 계약이 적용되며 국문이 우선합니다. 판매자는 효르에이아이테크 유한회사입니다.

07 설정

고객의 도구

코딩 에이전트를 플릿에 연결하세요.

계정에서 API 키를 만들어 도구에 설정하세요. 요청은 그 순간 고객이 보유한 플릿으로 가며, 지정한 모델이 적재되어 있지 않으면 플릿이 그 모델을 적재합니다.

보유 중인 플릿shell
# Claude Code
export ANTHROPIC_BASE_URL=https://sparkpipe.ai/pay/api
export ANTHROPIC_AUTH_TOKEN=계정에서 받은 키
export ANTHROPIC_MODEL=kimi-k3
export CLAUDE_CODE_MAX_CONTEXT_TOKENS=1000000

# Codex: ~/.codex/config.toml
model = "kimi-k3"
model_provider = "sparkpipe"
[model_providers.sparkpipe]
name = "SparkPipe"
base_url = "https://sparkpipe.ai/pay/api/v1"
env_key = "SPARKPIPE_API_KEY"
wire_api = "responses"

# Cursor, Aider 등 OpenAI 호환 도구
export OPENAI_BASE_URL=https://sparkpipe.ai/pay/api/v1
export OPENAI_API_KEY=계정에서 받은 키

curl $OPENAI_BASE_URL/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -d '{"model": "kimi-k3", "messages": [{"role": "user", "content": "안녕하세요"}]}'

플릿을 여러 개 보유하고 있다면 "sparkpipe": {"fleet": "F3"}로 하나를 지정하세요. sparkpipe setup claude-code와 sparkpipe setup codex가 이 설정을 대신 써 줍니다. sparkpipe CLI는 터미널에서 예약, 업로드, 기능 시작과 아침 보고서 확인도 합니다.

08 속도

실측

캐시가 남는 플릿이 중요한 곳에서 빠릅니다.

126 tok/s

추측 디코딩으로 파일 전체를 다시 쓰는 Kimi K3. 없으면 15 tok/s. 출력은 모델 자신의 것입니다.

0.3–5초

대화가 캐시된 후속 턴의 첫 토큰까지, Kimi K3로 137,700토큰까지. 콜드 상태에서는 299초.

15.6분

플릿 하나에서 100만 토큰 Kimi K3 프롬프트를 처음부터 프리필하는 시간. 나만의 플릿에서는 쉴 때마다가 아니라 한 번만 치릅니다.

K3, 일반15.3
K3, 추측126.4
GLM 5.3, 일반27.6
GLM 5.3, 추측124.2
0tok/s, 단일 요청126

새로 쓰는 코드는 오늘 기준 Kimi K3가 단일 요청 16.2 tok/s로 디코딩합니다. 고객의 코드로 학습시킨 드래프트 모델이 플릿을 거기서 더 빠르게 만드는 방법입니다. 모든 수치는 플릿 1에서 측정했으며, 방법과 근거는 PERFORMANCE_STATUS.md(영문)에 있습니다.

09 기술

오픈 소스

작은 상자 16대, 프런티어 모델 하나.

대형 모델의 디코딩 속도는 가중치를 얼마나 빨리 읽느냐로 정해집니다. SparkPipe는 모든 가중치와 모든 캐시 항목을 플릿의 노드 16대에 나누어, 각 노드는 자기 몫인 16분의 1만 읽고, 부분 결과를 100 Gb/s RDMA 메시로 16~38마이크로초 만에 합칩니다. 엔진은 C와 CUDA로 처음부터 작성했으며 Apache 2.0 라이선스로 공개합니다.
