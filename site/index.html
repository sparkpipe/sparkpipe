The engine

Written from scratch for small unified-memory machines.

Sixteen DGX Sparks hold 2 TB of unified memory and stream about 4.4 TB/s. SparkPipe makes them behave like one machine. Its kernels, RDMA transport, tokenizer, scheduler and cache are its own C and CUDA, with no third-party inference framework underneath.

FIRMWARE

Models compile to drivers

Each model links into one driver from content-addressed, validated modules. At runtime there is no graph interpreter, no kernel search and no fallback.

EXACT

Replayable tokens

The same driver, weights, prompt and seed reproduce every token bit for bit, and each request logs what an off-node replay needs.

B1 → B1024

Built for every batch

Kernels exist for every row count from 1 to 1024. One weight read serves every request in the step, so throughput grows with the batch.

SCHEDULING

Priorities and deadlines

Every request carries a priority and a deadline. The batch engine ages priorities so nothing starves, and cancels work that runs past its deadline.

OPENAI API

One door for every model

A LiteLLM proxy routes by model name, streams tokens and issues keys. Any OpenAI SDK works unchanged.

2 TB

Datacenter models, desk-side

Sparks hold models that normally need a datacenter server. GLM 5.2, a 756 GB checkpoint, runs on eight of them.

The dual fabric

Two rails. One collective service.

The CRS804 is the all-to-all rail, not a fallback. Pairwise direct links add a second active rail. SparkPipe pins both routes and selects a topology-aware all-reduce from the exact communicator, datatype, and payload bytes.

Measured fabric

The rails add. They do not substitute.

For large tensors, two counter-rotating half-payload rings alternate direct and switched edges. Every Spark overlaps direct TX/RX with switch TX/RX, cutting switch-facing bytes in half while keeping the switch inside the active collective.

How it works

Pin the routes. Profile the bytes. Select in O(1).

STEP 01

Admit by priority

Each request names a model, priority, and deadline. Interactive chat and agent populations enter the same scheduler.

STEP 02

Shape the work

The scheduler chooses placement, batch width, stage microbatch, speculation, and collective from the ready work and measured profiles.

STEP 03

Keep hardware occupied

Resident models run immediately; warm models promote atomically from verified NVMe tiers while unrelated ready work continues.

One serving engine, every scale

Deploy 4, 8, or 16 Sparks, then add DGX Stations in 1x, 2x, 4x, or 8x configurations. Large MoE models stay TP4 × PP4 on sixteen Sparks; smaller dense models can remain TP16. Expansion preserves the API, packages, scheduler, and evidence rules.

Every frontier model stays addressable

The scheduler mixes high-priority interactive chat with dense agent batches. Active models stay resident; others promote from verified NVMe tiers in at most 60 seconds. Targets include DeepSeek V4, GLM 5.2, Kimi K3, MiniMax H3, and Qwen 3.8 Pro and 27B.

The API

Any OpenAI client works.

SparkPipe's front door is a LiteLLM proxy: one OpenAI-compatible endpoint that routes by model name, streams tokens and issues keys. SparkPipe adds exact seeds and per-request deadlines.

The provider network · in development

Sell the capacity you are not using.

Connect your SparkPipe installation to sparkpipe.ai and rent out the hours your own traffic leaves idle. You choose the models and set the price. Every provider is validated, so all offers of the same model and quantization are interchangeable, and one buyer's requests can run on many providers at once.

85%

Your price, your share

You set the price per million tokens for each model. You keep 85% of what buyers pay; sparkpipe.ai keeps 15%.

1 frame

Your traffic comes first

Network work runs at the lowest priority and yields at the next frame boundary when your own requests arrive.

~2%

Every provider validated

About 2% of served tokens are recomputed on reference nodes with the exact published weights, to catch quantized or substituted models.

1 fabric

One private network

Providers, the router and the reference nodes share one tailnet. Your installation opens no port to the internet.
