Sixteen small boxes. One frontier model.

SparkPipe makes sixteen desk-side DGX Spark computers serve open models that normally need a datacenter server. Kimi K3 runs all 2.8 trillion parameters at the publisher's precision. The engine is written from scratch in C and CUDA, and the fleet runs on office power.

One machine

Every node reads one sixteenth. Every token.

Decoding is bound by memory bandwidth: a step takes about as long as reading its weights once. SparkPipe splits every weight and every cache entry so each node reads only its own sixteenth, then merges the partial results over a 100 Gb/s RDMA mesh. A 16-node collective takes 16 to 38 microseconds.

Without speculation, Kimi K3 decodes at 58% of the floor set by the bytes it reads per token. Speculation starts from there.

Built for agents

Long conversations, short turns.

A coding agent sends the same growing conversation again and again. In the coding-agent sessions we measured, the median step carried 270,000 tokens of context, and 97% of the input had been seen before.

SparkPipe keeps that prefix. Each node stores its sixteenth of it, so K3's 737,280-token window needs only 1.36 GB of cache per node, and the next turn computes only what is new. In testing, a 137,600-token prefix came back in 2.7 seconds after a round trip to another model.

Time to the first token of the next turn on Kimi K3. Cold: the whole conversation is computed. Cached: only the new turn is.

Speculation

Most of an edit is already in the context.

When an agent rewrites a file, most of what it writes is already in the conversation. SparkPipe drafts those tokens by looking them up in the request itself and checks up to 255 of them in one pass of the model. Where lookup finds nothing, a draft model on the hub's RTX 5090 proposes the next tokens. The target model verifies every draft, so the output is the model's own.

Measured on whole-file rewrites: Kimi K3 goes from 15 to 126-140 tok/s, GLM 5.3 Full from 28 to 233.

Sixteen models

      
Ask for a model. The fleet becomes it.

      
Sixteen models are installed, three of them for internal use only. One holds the fleet at a time. Name another in a request and SparkPipe swaps it in, in about a minute (K3 takes up to 79 s), and brings back its cached conversations. Every release must reproduce the previous build's tokens on six fixed prompts for every model.

What's different

      
Not a datacenter engine on smaller hardware.

      
Engines like vLLM and SGLang are built around GPUs that share one fast interconnect. SparkPipe starts from the other end: many small unified-memory boxes on Ethernet RDMA, where every byte read and every round trip counts.
