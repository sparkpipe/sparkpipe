01 루프라인

세 가지 물리 하한

모든 추론 단계는 세 개의 독립된 물리 하한을 따릅니다.

모델 M, 가속기 랭크 수 N인 하드웨어 프로필 H, 배치 크기 B, 컨텍스트 길이 C, 시퀀스당 포워드 행 수 R(Trows = B · R; 일반 디코드 R = 1, 추측 검증 R = K + 1, 프리필 R = L)에 대해 무손실 추론 엔진은 연산·메모리·네트워크 하한을 모두 만족해야 합니다.

1.1 연산 루프라인

Tcompute

Tc = (2·Pspine·Trows)/(N·TFspine) + (2·Pexp·Trows)/(N·TFexp) + Fattn/(N·TFbf16)

비전문가 스파인 FLOPs, 활성 라우팅 MoE 전문가 FLOPs, 그리고 유효 컨텍스트 Ceff(DSA/CSA2 희소 어텐션은 Csparse로 상한)에 대한 어텐션 FLOPs를 N개 랭크의 정밀도별 최고 TFLOPS와 대조합니다.

1.2 메모리 대역폭 루프라인

Tmemory

u(Trows,E,K) = 1 − (1 − K/E)Trows
Tm = (Wspine + Wexperts(u) + Wkv+idx+state) / (N·BWmem)

스텝당 한 번 읽는 스파인 가중치, 쿠폰 수집기 합집합 법칙 u(Trows, E, K)에 따른 라우팅 MoE 전문가 가중치(Trows=1에서 단일 토큰 활성 가중치를, 큰 배치에서 전체 전문가 풀을 정확히 복원), 그리고 KV 캐시·희소 인덱서·슬라이딩 윈도우·순환 상태(GDN/KDA) 트래픽을 합산합니다.

1.3 네트워크 집합통신 루프라인

Tnetworkmin

Tnmin = Rops·τhop + Rops·[2(N−1)/N]·(Trows·dh·2B) / BWnet

단일 랭크(N=1)에서는 0입니다. 다중 랭크 텐서 병렬에서는 L개 레이어 모델이 스텝당 최소 Rops = 2L회의 전체 히든 BF16 올리듀스를 수행하며, 홉 지연 τhop과 링 리듀스-스캐터/올게더 전송량 하한을 지불합니다.

중첩 기준 물리 하한은 Tfloor = max(Tcompute, Tmemory, Tnetworkmin)이며, 중첩이 없는 직렬 하한은 Tserial = Tc + Tm + Tnmin입니다. 그 비율 Goverlapmax = Tserial / Tfloor ∈ [1, 3]는 연산과 통신의 중첩으로 얻을 수 있는 최대 이득을 뜻합니다. 집합통신을 GEMM과 겹쳐 실행하는 엔진은 Tserial을 넘어 100에 가까워질 수 있는 반면, 직렬 실행 엔진은 100 / Goverlapmax에서 천장에 부딪힙니다.

02 5개 축

22.5%×4 + 10%

다섯 개의 직교 축과 열다섯 개의 세부 지표.

실제 서빙 환경은 엔진의 서로 다른 축을 압박합니다. RAIS v1.1은 90% 가중치를 네 개의 22.5% 핵심 런타임 축에 균등 배분하고, 10%를 100% 물리 하한 기반의 Pillar 5 — 운영·시스템 물리(축당 3개 지표)에 배정합니다.

P1 · 단일 스트림 디코드 · 22.5%

1a · 짧은 컨텍스트 B1 (C=256) · 10.8%
추측 디코딩을 끈(spec=OFF) B=1, 256 컨텍스트 일반 디코드. 100 × Tfloor / Tactual로 채점합니다.
1b · 긴 컨텍스트 B1 (C=64K–128K) · 8.1%
64K–128K(서빙 컨텍스트 상한 적용) 일반 디코드로 KV 스캔과 희소 인덱서 대역폭 비용을 드러냅니다.
1c · 꼬리 지터 (p50/p99 ITL) · 3.6%
B1 스트림의 토큰 간 지연 일관성: 100 × min(1, ITLp50 / ITLp99).

P2 · 추측 디코딩 · 22.5%

2a · 수락 품질 (α) · 10.8%
산문·코드·편집 워크로드 평균 라운드당 확정 토큰 α = E[A] + 1을 기준치 αref = 4.0으로 정규화: 100 × min(1, max(0, α − 1) / 3).
2b-i · B1 검증·드래프트 효율 (1/V) · 7.2%
K ∈ [4, 16]에서 검증 오버헤드 VB1 = α / (TPSspec / TPSnospec). 활성화 시 100 × min(1, 1/VB1), 미사용 시 0점.
2b-ii · B8 배치 검증 효율 (1/V) · 4.5%
B=8 배치 추측 검증 효율 100 × min(1, 1/VB8). 드래프터 품질(α)과 커널 검증 비용(V)을 분리해 진단합니다.

P3 · 배치·동시성 확장 · 22.5%

3a · 대화형 배치 (B=4, 8, 16) · 9.0%
B ∈ {4, 8, 16}의 Tfloor(B, 256) 대비 평균 효율. 스트림당 속도가 0.25 × TPSB1 SLA에 미달하면 비례 감점합니다.
3b · 고동시성 포화 (B=32, 64) · 8.1%
B ∈ {32, 64} 평균 효율. 동시성 상한으로 지원하지 않는 배치는 실제 동작한 최대 하위 배치의 합산 tok/s를 그대로 B의 루프라인에 대입해 감점합니다.
3c · 긴 컨텍스트 배치 (B=8 @ 32K–64K) · 5.4%
32K–64K 컨텍스트에서 8개 동시 스트림 디코드의 Tfloor(8, C) 대비 효율.

P4 · 프리필·멀티턴 에이전트 · 22.5%

4a · 대화형 콜드 프리필 (8K) · 7.2%
캐시 없는 8,192토큰 프롬프트의 첫 토큰 시간(TTFT)을 Tfloor,prefill(8192)와 대조합니다.
4b · 긴 콜드 프리필 (32K / 128K+) · 8.1%
캐시 없는 32K(40%)와 128K(60%, 서빙 상한 적용) 프리필의 물리 하한 대비 효율.
4c · 멀티턴 프리픽스·상태 재사용 TTFT · 7.2%
캐시된 후속 턴(8K+128 40%, 100K+128 60%)을 증분 프리필 하한 Tfloor,warm(Cprefix, 128)으로 채점합니다. 처음부터 재계산하면 0점에 가깝게 떨어집니다.

P5 · 운영·시스템 물리 · 10.0%

5a · 콜드 부트·모델 스왑 효율 · 5.0%
NVMe 순차 읽기 하한 Tbootfloor = max(1초, Wrank / BWNVMe) 기준 min(100, 100 × Tbootfloor / Tcold_boot). 미측정 시 0점.
5b · 가용 KV 메모리 효율 · 3.0%
여유 RAM 하한 Mfree = max(1 GiB, RAM − 가중치 − OS 예약) 기준 min(100, 100 × Musable_kv / Mfree). 미측정 시 0점.
5c · 배치 크기 비트 불변성 · 2.0%
결정론적 B=1 프롬프트(temperature=0, spec=OFF)를 혼합 B=8 배치의 0번 레인으로 동시 실행해 비트 일치 시 100점, 불일치 시 0점(INVALID 게이트와 분리).

단독 RAIS와 함께 순수 비추측 엔진 효율인 기본 루프라인 R = (P1 + P3 + P4) / 3, 추측 요약 (α, 1/VB1, 1/VB8), 표시 전용 스택 배지(Zero-NVIDIA NVRM + SKL CUDA 13.0 Apple Metal 4.0 — 수치 점수 영향 없음), 그리고 19개 표준 플릿 모델 가중 합산(티어 1 = 55%, 티어 2 = 25%, 티어 3 = 20%)을 함께 보고합니다.

05 무결성

이진 정확성 게이트

비트 정확성 없는 속도는 INVALID로 무효 처리됩니다.
